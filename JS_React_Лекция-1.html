Дорогие студенты-Яндексоиды. Сегодня разберём путь от голого JavaScript до React. Без воды: сначала база — функции и массивы, потом filter() и map(), а в конце соберём из этого настоящий интерфейс. Поехали.

01 · ОСНОВА

Функции — это станки

Функция — это станок: кладёшь сырьё на вход, получаешь готовое на выходе. Один раз настроил — пользуешься тысячу раз.

Смысл простой. У тебя есть кусок работы, который повторяется. Вместо того чтобы копировать его по всему коду, ты заворачиваешь его в функцию и зовёшь по имени. Поменялась логика — правишь в одном месте, а не в сорока.

functions.js
// станок: на вход имя, на выход приветствие
function greet(name) {
  return 'Привет, ' + name;
}

greet('Аня');   // 'Привет, Аня'
greet('Макс');  // 'Привет, Макс'

Сейчас чаще пишут стрелочные функции — короче и компактнее. Та же логика, меньше букв:

arrow.js
// то же самое, стрелочная запись
const greet = (name) => 'Привет, ' + name;

// если тело — одно выражение, return подразумевается
const double = (n) => n * 2;
double(21);  // 42
Макси

Стрелка => читается как «превращается в». n => n * 2 — «эн превращается в эн умножить на два». Запомнишь так — больше не будешь путаться.

▸ Зачем это нужно для React

React целиком построен на функциях. Каждый компонент — это функция, которая возвращает кусок интерфейса. Так что то, что ты сейчас читаешь, — фундамент под всё остальное.

02 · ДАННЫЕ

Массивы — это списки

Массив — пронумерованный список. Лента постов, товары в корзине, результаты поиска — под капотом всё это массивы.

Главное, что надо принять сразу: нумерация идёт с нуля. Первый элемент — это индекс 0, второй — индекс 1. Это не прихоть JS, так устроены вообще все языки. Привыкнешь.

массив fruits и его индексы
'яблоко'
[0]
'банан'
[1]
'манго'
[2]
'киви'
[3]
arrays.js
const fruits = ['яблоко', 'банан', 'манго', 'киви'];

fruits[0];        // 'яблоко' — первый
fruits[2];        // 'манго'
fruits.length;    // 4 — сколько всего
Рен

Почему с нуля? Индекс — это смещение от начала. Первый элемент стоит в самом начале, смещение ноль. Второй сдвинут на одну ячейку — смещение один. Память так и адресуется. Как только увидишь индекс как «насколько сдвинуться», вопросы отпадут.

Перебрать массив: цикл for

Когда надо пройтись по каждому элементу, нужен цикл. Классический for состоит из трёх частей: откуда стартуем, до каких пор идём, какой делаем шаг.

loop.js
//      старт     условие        шаг
for (let i = 0; i < fruits.length; i++) {
  console.log(fruits[i]);
}
// яблоко → банан → манго → киви

Но есть запись приятнее — for...of. Когда индекс не нужен, а нужны сами значения:

for-of.js
for (const fruit of fruits) {
  console.log(fruit);
}
// читается как русский: «для каждого fruit из fruits»
«индекс с нуля — это смещение, а не каприз»
03 · ОБРАБОТКА

filter() — фейсконтроль

filter() проходит по массиву и каждого спрашивает: «проходишь?». Кто ответил да — попадает в новый массив. Остальные остаются за дверью.

Ты даёшь функцию-условие. Она возвращает true или false. Всё, для чего вышло true, складывается в новый массив. Исходный массив не меняется — это важно, его никто не трогает.

filter(age => age >= 18)
[12, 25, 17, 30]
было
→
age => age >= 18
→
[25, 30]
прошли фейсконтроль
filter.js
const ages = [12, 25, 17, 30, 15, 22];

const adults = ages.filter(age => age >= 18);

adults;  // [25, 30, 22]
ages;    // [12, 25, 17, 30, 15, 22] — целый!
Кайл

На реальных проектах filter() — это поиск, фильтры в каталоге, отсев ошибок из логов, скрытие неактивных элементов. Один из самых частых методов в боевом коде, серьёзно.

Работает и со списком объектов — это как раз то, что приходит с сервера:

filter-objects.js
const products = [
  { name: 'Телефон', price: 15000, inStock: true },
  { name: 'Ноутбук', price: 80000, inStock: false },
  { name: 'Планшет', price: 25000, inStock: true },
];

// только то, что есть в наличии
const available = products.filter(p => p.inStock);

// только дешевле 30к
const cheap = products.filter(p => p.price < 30000);
▸ Частая ошибка новичков

filter ждёт true/false. Если забыть условие и просто написать filter(p => p.price) — оно тоже «сработает», но не так, как ты думаешь: любое ненулевое число считается за true. Всегда пиши явное сравнение.

04 · ОБРАБОТКА

map() — конвейер

map() прогоняет каждый элемент через функцию и выдаёт новый. Сколько элементов зашло — столько и вышло. Меняется содержимое, не количество.

Если filter() отсеивает, то map() преобразует. Зашло число — вышло удвоенное. Зашёл объект — вышло одно его поле. Зашли сырые данные — вышли в нужном формате.

map(n => n * 2)
[1, 2, 3, 4]
было (4 шт)
→
n => n * 2
→
[2, 4, 6, 8]
стало (тоже 4 шт)
map.js
const prices = [100, 200, 350];

// поднять все цены на 20%
const raised = prices.map(p => p * 1.2);
raised;  // [120, 240, 420]

// из объектов — вытащить только имена
const names = products.map(p => p.name);
names;   // ['Телефон', 'Ноутбук', 'Планшет']
Макси

Главное отличие держи в голове так: filter меняет длину, map — нет. filter может вернуть меньше элементов. map всегда вернёт ровно столько же, сколько было.

Цепочка: filter → map

Вот где начинается магия. Методы соединяются в цепочку — результат одного сразу идёт в следующий. Получил данные, отфильтровал, преобразовал — в три строки.

chain.js
const result = products
  .filter(p => p.inStock)      // 1. оставили в наличии
  .map(p => p.name);          // 2. взяли только имена

result;  // ['Телефон', 'Планшет']

05 · REACT

Компоненты — кубики Lego

React-приложение собирается из компонентов, как постройка из Lego. Компонент — это функция, которая возвращает кусок интерфейса.

Помнишь, в начале мы говорили, что функция — это станок? Так вот, компонент — это станок, который выдаёт не текст, а кусок страницы. Кнопка, карточка товара, шапка сайта — каждый такой кусок можно завернуть в отдельный компонент и переиспользовать.

Welcome.jsx
// простейший компонент — функция, возвращающая разметку
function Welcome() {
  return <h1>Привет, Яндексоиды!</h1>;
}

// используется как HTML-тег:
<Welcome />
Кайл

Заметь две вещи. Первое: имя компонента всегда с большой буквы — так React отличает твой компонент от обычного html-тега. Второе: вот эта странная смесь JS и HTML внутри называется JSX. Привыкнешь за день.

А дальше — компонент можно вкладывать в компонент. Так и строится дерево интерфейса:

дерево компонентов
<App />
<Header />
<ProductList />
<Footer />

App — это корень. Внутри — Header, список товаров и Footer. Каждый сам по себе.

06 · REACT

Props — данные сверху вниз

Props — это параметры компонента. Точно как аргументы функции: родитель передаёт данные ребёнку, и тот показывает что прислали.

Данные в React текут в одну сторону — сверху вниз. Родительский компонент передаёт значения дочернему через props. Дочерний их получает и отображает. Обратно данные так просто не ходят — это и есть «однонаправленный поток», за который React любят.

props текут вниз
<App />
name="Телефон" price={15000}
↓
<ProductCard />
ProductCard.jsx
// ребёнок принимает props и показывает их
function ProductCard(props) {
  return (
    <div>
      <h3>{props.name}</h3>
      <p>{props.price} ₽</p>
    </div>
  );
}

// родитель передаёт данные вниз
<ProductCard name="Телефон" price={15000} />
Рен

Почему поток только вниз? Так проще искать баги. Если на экране не то значение — ты точно знаешь, что оно пришло сверху, от родителя. Не надо гадать, кто и откуда его поменял. Предсказуемость дороже удобства.

▸ Фигурные скобки в JSX

Внутри разметки { } — это «здесь будет JavaScript». {props.name} значит «вставь сюда значение из JS». Текст пишем как есть, а динамику — в скобках.

07 · REACT × MAP

map() рисует списки

Вот ради чего всё затевалось. В React списки на экране рисуются через тот самый .map(). Массив данных превращается в массив компонентов.

Логика та же, что в начале лекции. map() берёт массив и преобразует каждый элемент. Только теперь он преобразует не число в число, а объект с данными — в кусок интерфейса. Массив товаров → массив карточек. Массив сообщений → массив пузырьков чата.

данные превращаются в интерфейс
[
 {name:'Телефон'},
 {name:'Планшет'}
]
массив данных
→
.map(p => <Card />)
→
<Card 'Телефон'/>
<Card 'Планшет'/>
массив карточек
ProductList.jsx
function ProductList() {
  const products = [
    { id: 1, name: 'Телефон', price: 15000 },
    { id: 2, name: 'Планшет', price: 25000 },
  ];

  return (
    <div>
      {products.map(p => (
        <ProductCard
          key={p.id}
          name={p.name}
          price={p.price}
        />
      ))}
    </div>
  );
}
Кайл

Смотри, что произошло. Мы взяли массив products и через .map() превратили каждый объект в <ProductCard />, прокинув данные через props. Это связало всё, что мы учили: массивы, map, компоненты и props в одной конструкции. Вот так и выглядит реальная разработка.

▸ Зачем key={p.id}

Когда рисуешь список через map, React требует уникальный key у каждого элемента. По нему он понимает, что изменилось, и не перерисовывает весь список целиком. Забудешь key — получишь предупреждение в консоли и тормоза. Бери id, а не индекс массива.

08 · REACT

Состояние — память компонента

Props приходят сверху и не меняются. А состояние (state) — это собственная память компонента, которая живёт и меняется от действий пользователя.

Нажал лайк — счётчик вырос. Отметил задачу — она зачеркнулась. Эти изменения хранятся в состоянии. В React за это отвечает useState. И вот ключевой момент: когда состояние меняется, React сам перерисовывает компонент. Тебе не надо вручную лезть в DOM — поменял данные, интерфейс обновился сам.

Counter.jsx
import { useState } from 'react';

function Counter() {
  // [значение, функция-меняла] = useState(начало)
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Лайков: {count}
    </button>
  );
}
Макси

Разбор строки const [count, setCount] = useState(0): count — текущее значение, setCount — функция чтобы его поменять, 0 — стартовое значение. Менять count напрямую нельзя, только через setCount — иначе React не заметит и не перерисует.

События: реагируем на клик

Видел onClick в коде выше? Это обработчик события. Пользователь кликнул — вызвалась функция. Точно так же есть onChange для полей ввода, onSubmit для форм и так далее.

Раздел 01 · Вёрстка

Контейнеры и раскладка в React

Прежде чем красить кнопки, надо понять как располагать блоки. В React вёрстка живёт прямо в компоненте — это JSX. Разберём контейнеры, вложенность и две главные системы раскладки: flex и grid. С живой песочницей.

Кайл

Дорогие студенты-Яндексоиды, начнём с каркаса. Интерфейс — это коробки в коробках. Освоишь как ставить коробки рядом и друг под другом — соберёшь любой макет. Остальное косметика.

01 · JSX

Разметка прямо в коде

JSX — это HTML, который умеет в JavaScript. Компонент возвращает разметку, а в фигурных скобках можно вставлять переменные и логику.

Главное правило: компонент возвращает один корневой контейнер. Всё остальное вкладывается внутрь. Обычно корень — это div или фрагмент <>...</>.

Card.jsx
function Card() {
  const title = 'Отель у моря';
  const price = 4500;

  return (
    <div className="card">         {/* корневой контейнер */}
      <h3>{title}</h3>             {/* переменная в скобках */}
      <p>{price}  / </p>
      {price < 5000 && <span></span>}  {/* логика прямо тут */}
    </div>
  );
}
className вместо class

В JSX атрибут класса называется className, а не class. Это потому что class — зарезервированное слово в JS. Единственная неожиданность, к которой привыкаешь за день.

02 · КОНТЕЙНЕРЫ

Коробка в коробке

Любой блок — это коробка с тремя кольцами: content (содержимое), padding (отступ внутри, до рамки) и margin (отступ снаружи, между коробками). Путаница padding/margin — причина 80% кривых макетов у новичков.

padding — внутри
margin — снаружи
отодвигает содержимое ОТ края коробки кнопка стала «толще» внутри её фона
отодвигает коробку ОТ соседей расстояние МЕЖДУ карточками
Рен

Мнемоника: padding — это вата внутри коробки вокруг товара. margin — это пустое место на полке между коробками. Перепутаешь — либо текст прилипнет к рамке, либо карточки слипнутся.

03 · FLEX vs GRID

Две системы раскладки

Есть два инструмента, чтобы расставлять коробки. Они закрывают почти всё.

  • Flexbox — одна ось. Поставить элементы в ряд или в колонку, распределить пространство между ними. Меню, тулбары, карточка с иконкой и текстом.
  • Grid — две оси сразу. Настоящая сетка строк и столбцов. Галереи, каталоги, дашборды, сетка слотов букинга.
Правило выбора

Элементы в линию (ряд ИЛИ колонка) — flex. Сетка строк И столбцов одновременно — grid. Если сомневаешься между ними, скорее всего тебе нужен flex.

Раздел 02 · Tailwind

Tailwind CSS: стили классами

Вместо отдельных css-файлов с придуманными именами — набор готовых классов-утилит прямо в разметке. Звучит дико, на практике быстро. Разберём идею и пощупаем на живой карточке.

Кайл

Обычный CSS: придумай имя класса, открой другой файл, напиши правила, свяжи. Tailwind: пишешь p-4 bg-red-500 rounded-xl прямо на элементе. Меньше прыжков между файлами, меньше выдуманных названий.

01 · ИДЕЯ

Utility-first

Каждый класс делает одну маленькую вещь. Из мелких кирпичей собираешь любой вид.

  • p-4 — padding 16px. m-2 — margin 8px. Шкала кратна 4px.
  • flex, grid, gap-3 — раскладка, та самая из прошлого раздела.
  • bg-red-500, text-white — цвета по палитре.
  • rounded-xl, shadow-lg — скругление, тень.
  • hover:bg-red-600, md:flex-row, dark:bg-slate-800 — состояния, адаптив и тёмная тема прямо в классе.
02 · CSS vs TAILWIND

Тот же результат

Одна и та же карточка двумя способами. Слева классика, справа Tailwind.

обычный CSS
Tailwind
/* styles.css */ .card { padding: 16px; background: #fff; border-radius: 12px; box-shadow: 0 4px 12px #0002; } <div class="card">
<!-- всё в разметке --> <div class=" p-4 bg-white rounded-xl shadow-md ">
Честный минус

Разметка становится длиннее и пёстрая от классов. Это плата за скорость. Лечится тем, что повторяющиеся куски выносишь в компоненты — и класс-строка пишется один раз на весь проект.

Раздел 03 · Логика

Пропсы, хуки, состояние и события

Каркас есть, стили есть. Теперь оживляем. Как данные текут в компоненты (пропсы), как компонент помнит (состояние), как реагирует на клики (события) и как рисует списки (map). Всё с живыми демками.

Кайл

Четыре кита React: пропсы передают данные вниз, состояние хранит что меняется, события ловят действия юзера, рендер перерисовывает картинку. Разберём по одному.

01 · PROPS

Данные текут вниз

Props — это аргументы компонента. Родитель передаёт, ребёнок получает и только читает. Менять их ребёнку нельзя — поток строго сверху вниз.

props flow — родитель → ребёнок
<App/> (родитель)
→
props
<UserCard/> (ребёнок)

Аня
это значение пришло пропсом
props.jsx
// ребёнок принимает props и только читает их
function UserCard({ name }) {
  return <div className="card">{name}</div>;
}

// родитель передаёт данные вниз
function App() {
  return <UserCard name="Аня" />;
}
Props read-only

Ребёнок не имеет права менять свои props. Если данные должны меняться от действий — это уже не props, это состояние. Об этом ниже.

02 · useState

Память компонента

Хук useState даёт компоненту память. Возвращает текущее значение и функцию-сеттер. Вызвал сеттер — React перерисовывает компонент с новым значением. В этом вся суть реактивности: меняешь состояние → картинка обновляется сама.

Counter.jsx
function Counter() {
  const [count, setCount] = useState(0);   // [значение, сеттер]

  return (
    <button onClick={() => setCount(count + 1)}>
      : {count}
    </button>
  );
}
// каждый setCount запускает новый рендер с новым count
live useState
0
состояние изменилось → перерисовок: 0
Макси

Видишь счётчик «перерисовок»? Каждое изменение состояния = новый рендер. Компонент не правит DOM руками, он просто описывает «как выглядеть при таком состоянии», а React сам обновляет экран.

03 · СОБЫТИЯ

Реакция на действия

События — это мост от юзера к состоянию. onClick, onChange, onSubmit. Внутри обработчика обычно вызываешь сеттер состояния. Клик → setState → рендер. Этот цикл ты уже видел выше: кнопки +1 это onClick, а поле имени в пропсах — onChange.

useEffect — на будущее

Есть ещё хук useEffect для побочных эффектов: загрузить данные при появлении компонента, подписаться на что-то. Грубо: «сделай вот это после рендера / когда поменялось вот это». Глубоко копнём отдельно, пока просто знай что он есть.

04 · map()

Рисуем коллекции

Список данных → список элементов. array.map() превращает каждый объект в JSX. Это самый частый паттерн рендера во всём React.

Рен

Один нюанс, который все забывают: каждому элементу списка нужен уникальный key. По нему React понимает, что изменилось, и не перерисовывает весь список зря. key — это id из данных, не индекс массива.

map.js
// данные (пришли бы с сервера)
const todos = [
  { id: 1, t: 'Забронировать отель' },
  { id: 2, t: 'Купить билеты' },
  { id: 3, t: 'Собрать чемодан' },
];

// map превращает каждый объект в строку (в React — в JSX)
const rendered = todos.map(todo => `[ ] ${todo.t}  (key=${todo.id})`);
rendered.forEach(line => console.log(line));
console.log('всего элементов:', todos.length);
console

Раздел 04 · Глобальный стейт

Глобальные данные и переключатель тем

useState хорош для одного компонента. А если состояние нужно половине приложения — например тема оформления? Тогда его поднимают глобально. Тема — идеальный пример. Сейчас включим её наглядно.

Кайл

Правило простое: состояние живёт настолько высоко, насколько широко оно нужно. Нужно одной кнопке — useState в ней. Нужно всему приложению — глобальный стор или Context. Тема нужна всем, значит глобально.

01 · ЛОКАЛЬНОЕ vs ГЛОБАЛЬНОЕ

Где держать состояние

  • Локальное (useState) — открыт ли этот конкретный дропдаун, текст в этом поле. Никому за пределами компонента не нужно.
  • Глобальное (стор / Context) — тема, текущий юзер, корзина, язык. Нужно во многих местах сразу, передавать пропсами через все слои — мучение (помнишь prop drilling из прошлой лекции?).
Связь с дата-менеджментом

Тут смыкается прошлая лекция: глобальный стейт — это работа Zustand или Context. Тема обычно лежит в маленьком сторе, и любой компонент берёт её оттуда напрямую, без протаскивания пропсов.

02 · ПЕРЕКЛЮЧАТЕЛЬ ТЕМ

Один флаг — весь интерфейс

Механика тёмной/светлой темы простая: где-то глобально лежит флаг theme. Компоненты не хранят цвета жёстко, а берут их из темы (через CSS-переменные или Tailwind dark:). Меняешь один флаг — перекрашивается всё разом. Жми тумблер:

03 · КАК ЭТО В КОДЕ

Тема в сторе + dark:

Два кусочка. Первый — глобальный флаг темы (тут на Zustand, как в прошлой лекции). Второй — компоненты, которые описывают оба варианта цвета через dark:, а Tailwind сам подставит нужный по классу на корне.

themeStore.ts
import { create } from 'zustand';

export const useTheme = create((set) => ({
  dark: true,
  toggle: () => set((s) => ({ dark: !s.dark })),
}));

// на корне приложения вешаем класс
function App() {
  const dark = useTheme((s) => s.dark);
  return <div className={dark ? 'dark' : ''}>...</div>;
}
Card.jsx
// компонент описывает ОБА варианта — Tailwind выберет по теме
function Card() {
  const toggle = useTheme((s) => s.toggle);
  return (
    <div className="bg-white text-slate-900
                    dark:bg-slate-800 dark:text-slate-100
                    p-4 rounded-xl">
      <button onClick={toggle}> </button>
    </div>
  );
}
Суть

Компонент не знает, какая тема активна. Он просто говорит «в светлой я белый, в тёмной — тёмно-серый». Решение принимает один флаг наверху. Это и есть сила глобального состояния: одна точка правды, много реагирующих компонентов.

Тёмная тема придумана не для красоты, а для тех, кто пишет код в три часа ночи.

Раздел 05 · Сборка

Онлайн-букинг по FSD

Финал. Соберём настоящий кусок интерфейса — выбор времени для бронирования — и разложим его по слоям FSD. Тут встретится всё: контейнеры, Tailwind, пропсы, состояние, события, map и тема. Демо ниже полностью кликабельно.

Кайл

Дорогие студенты-Яндексоиды, вот ради чего всё было. Сейчас увидишь, как четыре кита React и архитектура FSD складываются в живой экран бронирования. Каждый кусок — на своём слое.

01 · РАЗБОР ПО СЛОЯМ

Кто за что отвечает

Экран букинга по FSD разрезается ровно так:

src/ ├─ entities/slot/ # бизнес-сущность «слот времени» │ ├─ ui/ SlotCard.tsx # как выглядит один слот (props: time, price) │ ├─ model/ store.ts # zustand: выбранный слот, занятые │ └─ api/ getSlots.ts # fetch слотов с сервера ├─ features/select-slot/ # действие: выбрать слот (onClick → стор) ├─ widgets/BookingBoard/ # сетка слотов + summary (map по слотам) └─ pages/BookingPage/ # собирает виджет на странице
02 · ДЕМО

Живой экран бронирования

Кликай слоты — это события + состояние. Сетка нарисована через map(), каждому слоту передаются пропсы (время, цена). Тумблер справа — глобальная тема. Кнопка «Забронировать» меняет стор, и сетка перерисовывается.

Рен

Разбери глазами: серые перечёркнутые слоты — taken из данных, на них нет onClick. Выбранный красный — это поле selected в сторе. Сумма и кнопка реагируют на стор. Нажал «Забронировать» — слот стал taken, стор обновился, map перерисовал сетку. Никакого ручного трогания DOM.

03 · КОД ВИДЖЕТА

Всё вместе в одном компоненте

Вот как это выглядит в коде. Состояние из стора, map по слотам, пропсы вниз в SlotCard, onClick наверх в стор, Tailwind для вида, dark: для темы.

BookingBoard.tsx
function BookingBoard() {
  const { slots, selected, select } = useBooking();   // глобальный стор

  return (
    <div className="grid grid-cols-4 gap-3 dark:bg-slate-900">
      {slots.map((slot) => (              // map по коллекции
        <SlotCard
          key={slot.id}                   // уникальный key
          time={slot.time}                // props вниз
          price={slot.price}
          selected={slot.id === selected}
          disabled={slot.taken}
          onSelect={() => select(slot.id)} // событие наверх в стор
        />
      ))}
    </div>
  );
}
SlotCard.tsx
// чистый презентационный компонент — только props, своего состояния нет
function SlotCard({ time, price, selected, disabled, onSelect }) {
  return (
    <button
      disabled={disabled}
      onClick={onSelect}
      className={`p-3 rounded-xl text-center transition
        ${selected ? 'bg-red-500 text-white' : 'bg-slate-100 dark:bg-slate-700'}
        ${disabled ? 'opacity-30 line-through' : 'hover:-translate-y-1'}`}
    >
      <div className="font-mono font-bold">{time}</div>
      <div className="text-xs opacity-80">{price}</div>
    </button>
  );
}
Кайл

Вот и вся картина, Яндексоиды. SlotCard ничего не знает и не помнит — только принимает пропсы и зовёт onSelect. Вся память (что выбрано, что занято) в сторе. Виджет через map раздаёт данные карточкам. Тема сверху красит всё. Каждый кусок на своём слое FSD, и потому его легко найти, заменить и не сломать остальное. Это и есть хорошая архитектура.
